# nexusCLI 参考项目差距四项补齐任务包 - 项目范围

## 1. 问题定义

- **项目目标**：对照同类 Agent CLI 项目的「项目亮点」清单与课程目录（用户提供截图，2026-10-11 评估），把 nexusCLI 尚缺的四项能力落成可验收的产品功能：G1 Agent 评测回归、G2 工具循环调用检测、G3 run 级授权、G4+G5 跨会话历史搜索与 usage 续算。
- **目标用户**：nexusCLI 的开发者（评测回归、usage 口径）与 BYOK 本地 CLI 用户（审批分级、历史搜索）。
- **核心价值**：对照口径从「课程目录 13 项全齐、亮点 8 项缺 4 处」变为「亮点可评估项全齐」；每项带测试与如实文档。

## 2. 假设与待确认

### 2.1 已确认事实

- 基线（2026-10-11 本机实测，前一提交 3167e62）：`uv run python -m pytest` → 590 passed（含本包净增约 100 个测试）；`uv run ruff check .` → All checks passed!；`uv run ruff format --check .` → 171 files already formatted。
- 评估结论（截图逐项对照）：课程目录 13 项全有；亮点清单缺口为：任务级评测回归（无）、循环调用检测（无，仅 max_turns 兜底）、审批缺 run 级（仅 y 单次/a 会话/config 全局）、跨会话历史搜索（无）、恢复会话 usage 从零重计（README 声明的边界）。
- 亮点清单第 6 条在截图中被截断，未纳入评估（如实挂账）。
- 实现方式：动态工作流四工位并行（文件边界互斥）→ 独立复审 → 集成修复与文档 → 全量校验门，实现与复审由 GLM-5.3-Flash 子代理执行，规划与验收在主线。

### 2.2 关键假设

- 评测回归采用离线剧本式假 LLM（复用 tests 的假客户端模式），不依赖真实 LLM；真实 LLM 冒烟另行执行（同日已完成 3/3 路径通过，证据在会话记录与 .zcode/smoke/）。
- run 级授权语义定界为「主代理当前 agent run」，不传导子代理（子代理每次新建独立 ToolContext），该边界已写入 docs/subagents.md。
