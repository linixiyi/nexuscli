Runtime API

本文是 README「📡 Runtime API」章节的完整版。

NexusCLI 内置轻量 Runtime API，适合外部系统接入线程、turn、事件和后台任务。

启动服务：

NEXUSCLI_RUNTIME_API_KEY=dev-key \
uv run nexuscli serve --http --port 8080

创建线程：

curl -sS -X POST http://127.0.0.1:8080/v1/threads \
  -H 'x-api-key: dev-key'

发送 turn：

curl -sS -X POST http://127.0.0.1:8080/v1/threads/<thread_id>/turns \
  -H 'content-type: application/json' \
  -H 'x-api-key: dev-key' \
  -d '{"message":"总结这个项目"}'

读取事件：

curl -sS http://127.0.0.1:8080/v1/threads/<thread_id>/events \
  -H 'x-api-key: dev-key'

创建并查看后台任务：

curl -sS -X POST http://127.0.0.1:8080/v1/tasks \
  -H 'content-type: application/json' \
  -H 'x-api-key: dev-key' \
  -d '{"message":"后台总结这个仓库","mode":"plan"}'

curl -sS http://127.0.0.1:8080/v1/tasks \
  -H 'x-api-key: dev-key'

也可以只启动队列消费者，不暴露 HTTP：

uv run nexuscli worker --workers 2 --cwd .

任务队列按项目目录隔离；worker 使用 SQLite 原子事务领取任务，并通过 lease/heartbeat 恢复崩溃任务。运行中取消会阻止 worker 把迟到结果重新覆盖为 completed。

工作台浏览器会话（bootstrap/cookie/csrf）

上面的 curl 示例全部走外部自动化通道（x-api-key 头）。--workbench 启动的可视化 工作台另有一套浏览器会话鉴权语义（实现见 src/nexuscli/runtime/api.py 的 _handle/_handle_bootstrap 与 src/nexuscli/runtime/websession.py）：

  • 一次性 bootstrap 口令：服务启动生成一次性口令并在终端打印 http://127.0.0.1:<port>/#bootstrap=<token> 一键链接；浏览器打开后前端读出 URL 片段中的口令（随即抹除，token 不留地址栏），POST /v1/workbench/bootstrap 一次性 换发——口令错误或重放一律 403。该端点免 cookie/key 门：口令本身即凭证。
  • HttpOnly cookie 会话：换发成功即 Set-Cookie（HttpOnly，JS 不可读； SameSite=strict，跨站不携带），之后浏览器请求同源自动携带 cookie 作为凭证。
  • x-csrf-token：仅凭 cookie 通过会话门的变更请求（POST）必须另带 x-csrf-token 头（bootstrap 响应体返回，前端存内存不落 localStorage）——cookie 自动携带挡不住 跨源伪造，csrf 补上这一刀；api_key 通道豁免（外部程序没有 cookie，凭证本身就是 凭据）。
  • Origin 白名单：/v1/* 上任何带 Origin 头且来源非本机回环的请求一律 403， 且先于凭证判断（无凭证也拒绝跨源探测）；无 Origin 的 curl 等非浏览器客户端 不受影响。
  • 三通道三选一：会话门接受 x-api-key/Bearer 头、SSE 的 api_key 查询参数 （仅 SSE 路径）、HttpOnly cookie 三者之一。外部通道原样保留，本文所有 curl 示例 无需改动。

会话生命周期 = 进程生命周期：不持久化、不刷新，重启即新一轮口令；静态资源免鉴权 （构建产物无用户数据）。功能面与端点清单见 workbench.md。 drift line

部署边界

  • 服务端只绑定 127.0.0.1，面向单用户本机自动化；不做多用户认证与公网部署。
  • AGPLv3 §13 源码提供义务：本项目按 AGPL-3.0-only 授权。把 Runtime API（或其修改版）作为网络服务对外提供时，须向交互用户提供对应源码（自托管即天然满足；修改后对外服务则须提供修改版源码）。
